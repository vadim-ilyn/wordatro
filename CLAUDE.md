## 1. Что за проект

**Wordatro** — браузерная игра в жанре **Balatro + Word Association**. Карточный roguelike: игрок получает карты со словами из разных категорий, угадывает к какой категории относится каждое слово, и собирает на доске карты одной категории чтобы набрать очки.

**Ключевая механика**: категория слова на карте **не отображается** — игрок угадывает её сам. В этом весь геймплейный челлендж.

---

## 2. Технологический стек

- **Vanilla JavaScript** (ES Modules, без TypeScript)
- **HTML5 + CSS3** (DOM-карты, не Canvas)
- **HTML5 Drag and Drop API** для перетаскивания карт
- **Никаких npm/Vite/Webpack** — проект запускается прямым открытием
- Для `fetch()` JSON-конфигов нужен HTTP-сервер: подойдёт `python3 -m http.server` или VS Code Live Server

**Браузеры**: современные десктопные (Chrome, Firefox, Safari, Edge). Mobile — не приоритет в первом проходе.

## 5. Архитектурные принципы

### 5.1 Разделение логики и UI
- Папка `src/game/` — **чистая логика без DOM**. Можно тестировать в Node.js.
- Папка `src/ui/` — **только рендер и события**. Не содержит бизнес-логики.
- Связь через `GameState`: UI слушает изменения, логика только обновляет state.

### 5.2 GameState — единый источник правды
Состояние всей игры хранится в одном объекте. Примерная форма:

```js
{
  level: {
    id: 1,
    targetPoints: 100,
    categories: [...],          // из level_X.json
  },
  deck: [],                     // массив карт ещё в колоде
  playerHand: [],               // карты в руке
  wordSlots: [null, null, ...], // 8 ячеек на доске
  exchanger: [],                // карты в exchanger
  score: 0,                     // текущий счёт
  handsLeft: 3,                 // оставшиеся попытки Play
  replaceAttemptsLeft: 3,       // оставшиеся попытки Replace
  phase: 'PLAYER_TURN',         // см. state machine в GUI_SPEC.md
}
```

### 5.3 Не хардкодить числа
Все параметры — из конфигов:
- `start_hand_size`, `play_cards_slots_amount`, `hands_count`, `replace_attempts_count`, `max_cards_replace_count`, `points_progression` → из `game_config.json`
- `target_points`, `categories`, `bonus_points` → из `level_X.json`

### 5.4 Drag&Drop
Использовать **нативный HTML5 Drag and Drop API**, не подключать библиотеки. Общая логика drag&drop живёт в `src/ui/DragDrop.js`. Каждый дроп-таргет (`WordSlot`, `Exchanger`, `PlayerHand`) регистрируется через эту систему.

## 6. Игровая логика — ключевые правила

> Полные правила в `docs/game.md`. Здесь — критичный summary, чтобы Claude Code не упускал нюансы.

### 6.1 Формирование колоды
1. Прочитать `level_X.json`
2. Собрать массив всех слов: `categories.flatMap(c => c.wordsIds)`
3. Для каждого слова создать `WordCard` с полями `{id, word, category, bonus: 0}`
4. **Перемешать** массив (Fisher–Yates shuffle)
5. Применить бонусы: взять `bonus_points` (например `[20, 30, 20, 50, 10, 10, 10, 10, 10, 10]`) и присвоить эти значения **N случайным уникальным картам** колоды (где N = длина массива `bonus_points`). Важно: карты с бонусами должны быть **разбросаны по всей колоде в случайном порядке**, не лежать подряд в начале — иначе игрок получит все бонусы в первой же руке.
6. Реализация: после шага 4 присвоить бонусы первым N картам, затем **повторно перемешать** колоду (Fisher–Yates). Это эквивалентно выбору N случайных уникальных индексов, но проще.

### 6.2 Определение категории-победителя
После Play:
1. Сгруппировать карты на `WordSlots` по `category`
2. Найти категории с **максимальным** числом карт
3. Если одна → она победитель
4. Если ничья → сравнить по сумме бонусов карт каждой категории, побеждает большая
5. Если и бонусы равны → взять первую категорию из претендентов

### 6.3 Подсчёт очков
```js
const winningCount = winningCards.length;
const basePoints = points_progression[winningCount - 1]; // [10,20,30,50,100,250,500,1000]
const bonusSum = winningCards.reduce((s, c) => s + c.bonus, 0);
const totalPoints = basePoints + bonusSum;
```

### 6.4 Жизненный цикл хода
См. **State Machine** в `GUI_SPEC.md` раздел 14. Кратко:
`PLAYER_TURN → SCORING → REFILL → CHECK_END → (PLAYER_TURN | LEVEL_COMPLETE | GAME_OVER)`

**Условия выхода в `CHECK_END`** (порядок проверки важен):
1. Если `score >= target_points` → `LEVEL_COMPLETE` (досрочный win: уровень считается пройденным сразу, даже если `handsLeft > 0`. Доигрывать оставшиеся руки нельзя).
2. Иначе если `handsLeft <= 0` → `GAME_OVER`.
3. Иначе → обратно в `PLAYER_TURN`.

### 6.5 Что НЕ показывать игроку
- Категория карты — данные есть, на UI **никогда не отображать**
- Состав колоды — игрок не должен видеть какие карты ещё остались

## 7. UI — критичные напоминания

> Полная спецификация в `docs/GUI_SPEC.md`. Здесь — топ-правил, которые легко нарушить.

### 7.1 BonusBadge
- `bonus === 0` → плашка **полностью скрыта**, не показывать "+0"
- Цвет по конкретному значению (10=зелёный, 20=синий, 30=пурпурный, 50=золотой)
- Позиция: правый верхний угол карты

### 7.2 Disabled-состояние кнопок
- `PlayButton` — disabled когда `WordSlots` пуст
- `ReturnAllButton` — disabled когда `WordSlots` пуст
- `ReplaceButton` — disabled когда `Exchanger` пуст ИЛИ `replaceAttemptsLeft === 0`
- `ResetButton` — disabled когда `Exchanger` пуст
- Disabled = серый цвет `#888888`, без hover-эффекта

### 7.3 Анимация удаления проигравших карт
После Play:
1. Карты проигравших категорий получают класс `losing` → на них появляется красный крест ×
2. Через **1 секунду** карты удаляются с `WordSlots` с fade-out анимацией
3. Только после этого начинается фаза `REFILL`

### 7.4 Пропорция карт
Все карты (`WordCard`, `WordSlot`, `Deck`) — пропорция **3:4** (как `card-base.png` 240×328).

### 7.5 Визуализация подсчёта очков (ScorePopup)
После Play игрок должен **видеть математику начисления**. Простое тиканье общего счёта непрозрачно — игрок не понимает, почему именно столько очков.

Последовательность Play:
1. `SCORING` → крестики на проигравших картах (1 сек)
2. Удаление проигравших → на доске остались только winners
3. Появляется `ScorePopup` с разбивкой:
   - количество карт-winners × базовые очки (`points_progression[count-1]`)
   - сумма бонусных очков (желательно с разбивкой по бонусным картам: `+20 +30 +10 = +60`)
   - итог: `base + bonus = total`
   - изменение общего счёта: `scoreBefore → scoreAfter`
4. Popup висит ~1.5–2 сек (или закрывается по клику), потом исчезает
5. Только после этого winners тоже удаляются с доски, идёт `REFILL`, обновляется `ScoreProgressBar`

Категорию-победителя по имени **не показывать** (правило §6.5 сохраняется) — игрок видит её косвенно через карты, которые остались.

### 7.6 DeckComposition label
Над `DeckView` (стопкой колоды) показывается короткая плашка с составом колоды формата `N × M cards`, где **N** — число категорий в текущем уровне, **M** — количество карт в каждой категории (например `5 × 8 cards` для level 1: 5 категорий по 8 карт = 40 карт).

Цель — игрок видит структуру колоды и понимает, сколько потенциальных "семейств" слов он может собрать.

Правила:
- Текст **на английском** и **максимально короткий** (≤ 12 символов в строке)
- **Имена категорий НЕ показываются** (правило §6.5 сохраняется — игрок угадывает категории сам)
- Если у категорий разное количество слов — fallback: `T cards / N cats` (T = всего карт)

## 9. Code Style

### 9.1 JS
- ES Modules: `import` / `export`
- `const` по умолчанию, `let` только когда нужно
- Стрелочные функции для коллбеков, обычные функции для методов класса
- Без `var`
- Без точек с запятой — **с точками с запятой** (для однозначности парсинга)
- 2 пробела отступ

### 9.2 CSS
- BEM-подобный нейминг: `.word-card`, `.word-card__bonus-badge`, `.word-card--dragging`
- CSS-переменные для палитры в `:root`
- Без CSS-фреймворков

### 9.3 HTML
- Семантические теги где возможно
- Все интерактивные элементы — настоящие `<button>` (не `<div>` с onclick)
